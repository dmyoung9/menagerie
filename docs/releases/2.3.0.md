# Release 2.3.0

## Dashboard workflows

- Separate GPU and CPU/RAM trend cards, with per-device GPU lines and legends,
  current power/disk/swap values, clearer allocation contrast, and separate
  process-name and PID columns.
- Move telemetry sample and individual-run tables to **Settings → History**,
  while retaining resource summaries and charts on model/deployment details.
- Highlight installed model quantizations and suffixes above file details, use
  capability icon badges, and simplify discovery and model dialogs. Track model
  transfers in **Models → Downloads** with concrete repository/file identities.
- Edit deployments directly in **Configuration**, inspect raw settings in
  **Advanced**, and view deployment-scoped **Requests**. Unsaved changes are
  protected when navigating away.
- Show **Errored** deployment badges with log links, **N/A** for unloaded VRAM,
  and an em dash for missing measurements. Performance charts use retained runs
  of the same deployment and execution configuration, with gaps between runs.
- Consolidate activity into expandable **Events** with lifecycle steps, resource
  links and run-scoped logs. Pressure events include the measured resource,
  value and threshold. Remove global Sessions and historical-copy UI actions.
- Use compact engine rows with source actions in the toolbar and an inline
  Host policy form. The Prometheus `/metrics` endpoint remains supported and
  documented without a dashboard link.

## Limits and compatibility

Existing saved configurations are preserved. Older events and samples cannot
provide details that were never recorded; historical charts and run logs are
limited by retained data. Configuration changes require the deployment unloaded.
Resource estimates remain advisory and do not reserve memory or certify fit.

Automated checks use synthetic runtimes and fixtures, not real inference.
Windows 11 / RTX 5060 and Unraid GPU acceptance remain separate target-host
checks; release artifacts do not establish GPU compatibility, model quality,
memory fit or thermal safety. See the [release checklist](../release-validation.md).
