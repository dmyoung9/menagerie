# Release 2.5.0

## Independent variants

- Configure variants in an always-visible Variants card, independently of the
  Reasoning capability declaration. Client exposure, deployment defaults and
  gateway request transformations continue to work when Reasoning is off.
- Edit variants in a responsive Drawer with guided effort, thinking-toggle and
  token-budget controls, full Request JSON and optional prompt prefixes. Apply
  updates the builder draft; Save persists it. Unapplied edits have discard guards.
- Use compact rows with enablement switches, actions menus and Custom badges.
  Add variants from the card header and reorder them through Move up/down actions.
  Custom IDs are generated once and remain stable when renamed.

## Defaults and compatibility

- New configurations seed Instant, Low, Medium, High, XHigh and Max in that order.
  Only Low, Medium and High start enabled. Instant uses
  `chat_template_kwargs.enable_thinking: false`; the other choices use matching
  request-field effort values.
- Existing saved order, IDs, settings and exposure are preserved. Saved Ultra
  remains custom. Blank common choices receive editor defaults without rewriting
  stored settings on unrelated saves.
- New custom variants start disabled with medium effort. Empty mappings require
  a nonblank prompt prefix, except for legacy empty Default compatibility.
- Legacy Default rows remain editable and reorderable without an exposure switch;
  they do not control the client's built-in Default/no-variant choice. Saved flags
  and mappings are retained.

## Navigation fix

- Disabled deployments now open the filtered list correctly, including detail
  navigation, reload and browser Back/Forward. Legacy inactive links still work.

## Limits

Variant fields, effort names, template keywords and unlimited-budget sentinels
remain model/template/engine-specific. Configuring or enabling a variant does not
prove runtime support. See [model capabilities](../model-capabilities.md).
Saved model/runtime data is preserved; configuration edits still require unloaded
deployments. Plugin changes on disk do not reload an already-running client.
The existing OpenCode plugin dependency tree has moderate npm audit advisories;
this release does not update those dependencies or claim an advisory-free tree.

Automated verification uses synthetic runtimes and fixtures, not real inference.
Windows 11 / RTX 5060 and Unraid GPU acceptance remain separate target-host checks;
release builds do not certify model quality, memory fit, GPU compatibility or
thermal safety. See the [release checklist](../release-validation.md).
