# Release 2.4.0

## Deployment configuration

- Organize Configuration into open settings sections with jump navigation,
  a persistent Save/Discard bar and a responsive resource sidebar. Keep model,
  engine, template, multimodal, MTP, memory, generation and lifecycle settings
  together without nested tabs.
- Select compatible recorded projector and MTP-head companions instead of typing
  paths. None is the default; Embedded requires full-GGUF MTP metadata. Draft-token
  limits share a paired range slider with exact numeric inputs.
- Show engine-reported numeric defaults without saving them as overrides. Add
  supported sampling and speculative controls, and use Auto/On/Off radios for
  Flash Attention while preserving saved choices and cache restrictions.

## Reasoning levels

- Keep compact Instant/Low/Medium/High exposure toggles and add user-created
  custom levels to the same row. Preserve existing preset IDs and settings;
  unconfigured standard choices are not automatically saved or exposed.
- Combine supported native/template effort, thinking switches, budgets and
  template arguments through Custom request settings. Template arguments belong
  inside `chat_template_kwargs`; optional prompt prefixes affect only the latest
  user message, preserving history, system instructions, tools and content parts.
- Choose a deployment default independently of client exposure. Defaults fill
  missing request controls; explicit modes override only their configured fields.
  The `model-default` selector bypasses deployment defaults. Validate mode effects
  before loading a model, and retain OpenCode discovery compatibility.

## Dashboard and reliability

- Simplify deployment rows and actions, separate active requests from durable
  finished-request totals, use clearer status/log links and correct resource
  tooltip labels. Historical totals can only recover retained history.
- Use primary-green selections without checkmarks across capabilities, reasoning,
  installed quantizations and Discover variants. Keep capability badges uppercase
  and preserve keyboard and responsive behavior.
- Preserve saved template overrides in editor/duplicate drafts. Initialize durable
  request counters without sorting large session snapshots into temporary files,
  including when the service's system temporary directory is read-only.

## Compatibility and limits

Saved configurations and model/runtime data are preserved. Configuration edits
still require unloaded deployments and optimistic revision checks. Existing
engine defaults remain implicit unless edited. Resource estimates are advisory;
historical KV-cache estimation is not included.

Reasoning names, template keywords, budget fields and unlimited sentinels depend
on the selected artifact/template and engine; accepted JSON is not proof of model
support. See [reasoning configuration](../model-capabilities.md). Plugin changes
on disk do not reload an already-running client.

Automated checks use synthetic runtimes and fixtures, not real inference.
Windows 11 / RTX 5060 and Unraid GPU acceptance remain separate target-host checks;
release artifacts do not certify model quality, memory fit, GPU compatibility or
thermal safety. See the [release checklist](../release-validation.md).
