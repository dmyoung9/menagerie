# Menagerie 2.1.5

## First-class chat templates

Chat templates are now first-class objects with model-level and deployment-level
selection, rather than something inferred from the artifact.

- **Sources:** Automatic (engine default), Embedded (GGUF
  `tokenizer.chat_template` / safetensors `tokenizer_config.json`), Published
  (template files in the pinned Hugging Face commit: a root
  `chat_template.jinja` or a file under a `chat_templates/` directory), and
  Custom (user-authored).
- **Precedence:** deployment override > model default > engine default. The UI
  shows the **Effective** choice; there is no silent fallback.
- **Engine flags:** `--chat-template-file` for llama.cpp/Prism, `--chat-template`
  for vLLM. A manually set conflicting flag is rejected at save time instead of
  being silently shadowed by the selection.
- **Model Details → Chat templates:** set the model default, refresh (an
  Activity job that re-reads the pinned commit's template files and the artifact's
  embedded metadata, without moving or redownloading weights and without
  overwriting a custom template or an existing selection), list by source and
  status, and create, edit, or delete custom templates.
- **Deployments:** per-deployment override with an Effective readout in the
  deployment wizard, the member editor, and serving deployments.

A safetensors embedded template now points at the real
`tokenizer_config.json` in the snapshot; a selection whose asset is missing is
rejected at validate/launch time rather than launching without a template.
Deleting a model removes its template assets and the custom template files it
owns.

## Limitations

Template file downloads use the pinned commit and are re-read on refresh; a
refresh never moves or redownloads weights. Custom templates are stored under
`~/.config/menagerie/templates` (or the equivalent store root) and are the only
templates that can be edited or deleted. Automated checks use synthetic data
and fake runtimes, never real inference.
