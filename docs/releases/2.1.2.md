# Menagerie 2.1.2

## Native Windows installer

- Download `menagerie-2.1.2-windows-x64-setup.exe` from this release's **Assets**.
  Python, Node, Git, OpenCode, and WSL are not required to launch the application.
  The installer includes the dashboard and application dependencies.
- Install in your own account, then use **Menagerie** and **Stop Menagerie** from
  the Start Menu. Opening it again reuses the running instance. Closing the
  browser leaves serving running.
- Windows x64 managed llama.cpp acquisition supports CPU and available compatible
  CUDA builds, including verified companion DLL archives. NVIDIA drivers remain
  a host prerequisite; no driver or CUDA SDK installation is performed.
- State, managed engines and model references live outside the application
  directory and remain after upgrade or uninstall. Reinstallation reuses them.

See [Windows installation and recovery](../windows.md) for paths, port conflicts,
diagnostics and update/removal instructions. Verify the installer with its adjacent
`.sha256` file or the release's `SHA256SUMS`.

## Reliability and delivery

- Native Windows process ownership and process-tree cleanup, duplicate-start
  protection, explicit shutdown, Unicode/spaced paths and actionable loader errors.
- Missing Windows telemetry remains unavailable rather than being reported as
  measured zero. Reinstalling a removed engine retains registry history.
- Native CI verifies the installed application with a real-subprocess fake CPU
  worker, streaming/disconnection cleanup, restart, upgrade, uninstall and
  reinstall. Windows installers and checksums are now release assets alongside
  the Linux wheel, source archive and Unraid delivery files.

## Limitations and acceptance

- The Windows installer is unsigned. Actual browser, SmartScreen, Defender and
  firewall prompts need fresh-download review; do not disable host protections.
- Clean Windows 11 / RTX 5060 onboarding, real inference, streaming, cancellation,
  shutdown and hardware telemetry acceptance remain pending. Native CI uses a
  Windows Server runner and fake workers; it does not establish GPU support.
- Windows upgrade CI uses a synthetic older installer, not a historical Windows
  release. Automatic rollback, Windows services and an Electron shell are not
  provided. Windows CPU / Intel acceleration and WSL are separate acceptance work.
- Existing target-host Unraid and other GPU acceptance remains separate from
  automated packaging checks. No real inference runs in CI.
